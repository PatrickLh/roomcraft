# RoomCraft V1.0 执行计划

> 依据：`docs/v1.0.md`（2026-10-08 PRD）。计划日期：2026-10-09。
> 当前仓库仅有需求文档和 README，按从零搭建安排。本文是执行计划，不代表相关能力已验证或实现。

## 1. 需求分析与执行原则

产品主链路：上传户型图片 → AI 输出结构化户型 → 确定性生成可编辑 3D → 墙体修正与家具布局 → 风格参考图生成效果图 → 保存和分享。

技术方案与 V1 范围已明确，无阻塞计划拆分的问题。主要不确定性是视觉模型的结构识别与尺寸标定能力，以及生图 API 的布局保持能力，必须先通过真实样本验证。

- 户型 JSON Schema 是唯一事实源；3D 对象由结构化数据派生，不能成为独立存档源。
- 先验证能力，再完成“看 → 改 → 美 → 传”；M0 的 Spike 使用独立验证脚本，不开发完整产品流程。
- M0 的假户型双视角原型用于验证技术路径，可与 Spike 并行；正式业务接入依赖 Spike 结论。
- AI 调用、密钥、计数、限流全部在后端；识别和生图分别使用可替换的 Provider 适配层。
- 从首个生图验证产物开始加入显式 AI 标识和隐式元数据；正式流程覆盖预览、下载、历史与分享。
- 家具真实尺寸不开放自由缩放；重叠只警告，不阻止摆放。
- 每阶段产出可复现记录和验收证据；质量不过关时回到模型、提示词与管线验证，不靠增加功能掩盖。

## 2. 实施前需收敛的细节

以下不阻塞本计划，进入对应任务前确认并记录决策，不能默认为新增产品需求。

| 事项 | 执行安排 | 最晚确认点 |
|---|---|---|
| “用户自行配置模型与密钥”的用户身份 | 明确指部署维护者还是终端业主；M0 使用后端环境配置。若要求终端业主配置，需补充登录、密钥安全存储、权限、配额归属及界面设计 | M1 Provider 配置设计前 |
| 失败与重试的额度语义 | 建议成功结果结算一次，失败释放预占；生图自动重试最多一次且不重复扣减。明确解析成功、生图成功、取消与超时的结算边界 | M1 配额实现前 |
| 每日额度恢复时间与游客登录后的额度 | 明确业务时区、跨日处理、游客转账号后的额度合并规则；不能仅由前端控制 | M1 配额实现前 |
| 户型有效性与尺寸一致性 | M0 定义人工评分规程，验证后固化尺寸容差、结构错误分类、可用判定与重试提示 | M0 评测前 |
| 分享内容与隐私 | 建议分享当前方案快照及用户选定效果图；是否包含原始户型图片需明确，默认避免公开原图。明确撤销与更新行为 | M2 分享实现前 |
| 机位数量作用范围 | 明确每个房间还是整个方案提供 3–4 个机位，结合小房间、狭长房间的样例验证 | M3 机位实现前 |
| 视觉与操作参数 | 通过设计原型确定层高、墙厚默认值、材质、网格与吸附阈值、行走方式、切换动画 | M1 场景实现前 |
| 上传限制与数据保留 | 明确大小、分辨率、存储期限、删除规则和隐私政策；游客本地方案与 OSS 文件采用独立生命周期 | M1 上传实现前 |
| 合规发布条件 | ICP 并行推进；AI 标识实现和政策文本需在上线前核验，公开推广前落实 PRD 中的备案安排 | M4 发布前 |

## 3. 工作分解与里程碑

仅 M0 沿用 PRD 的 1–2 周时间预算。M1–M4 在 M0 结论、设计参数和人员投入明确后估时，不预设无法兑现的工期。

### M0：验证关键不确定性与技术路径（1–2 周）

| ID | 任务 | 交付物与验收 |
|---|---|---|
| M0-01 | 建立评测样本与评分规程 | 至少 10 张获授权真实户型图，标注电子图/翻拍图、尺寸是否可读、墙门窗与房间名基准；电子图单独统计，报告样本数量和误差类型 |
| M0-02 | Spike A：视觉模型识别 | 独立脚本输出候选户型 JSON，记录模型、提示词版本、耗时、成本和失败原因；多条尺寸交叉验证，不能标定则失败，不凭空猜测尺寸 |
| M0-03 | Spike B：布局与风格验证 | 用假场景截图和风格图调用商用参考图生图 API，记录布局保持和风格还原评分、耗时、成本；输出从首次生成就带 AI 标识 |
| M0-04 | 假户型场景技术原型 | Three.js 从固定 JSON 生成墙、门窗洞与地面；俯视旋转、行走观察、平滑切换可运行；验证尺寸和坐标约定 |
| M0-05 | 工程脚手架 | pnpm workspace：`apps/web`、`apps/server`、`packages/shared-schema`；后端依赖独立管理，通过根命令统一启动与校验；提供配置示例、开发说明和 CI 基础 |
| M0-06 | 评审并确定推进策略 | 提交评测报告和架构决策记录：Provider 候选、提示词方案、单位/坐标、限制与风险、继续或调整结论 |

执行顺序：M0-01 → M0-02；M0-03、M0-04、M0-05 可并行。Spike 不依赖产品脚手架完成。

出口门槛：

- 电子户型图结构可用率目标 ≥ 80%，效果图布局保持与风格还原主观可用率目标 ≥ 60%；按预先定义的评分规程计算，保存原始结果和人工评审记录。
- 10 张样本用于风险判断，不能据此宣称已经通过内测质量验收；后续持续扩充样本。
- Spike A 不达标：换模型、提示词或分阶段识别后复测，暂缓正式识别链路扩展。
- Spike B 不达标：换 API 或调整输入策略；若仍失败，明确评审是否将 V2 深度控制提前，更新范围后再执行，不暗中扩大 V1。
- 技术原型能从同一份 JSON 运行双视角，工程具备可启动、可校验的基础环境。

### M1：上传到 3D 的核心闭环

依赖：M0 评审通过；模型配置、配额语义与结构标准明确。

| ID | 任务 | 交付物与验收 |
|---|---|---|
| M1-01 | 定义共享 Schema 与生成流程 | 墙、端点、门窗洞、房间标签、尺寸、模型引用及 Schema 版本；统一单位和坐标；生成 TS 类型与 Pydantic 模型；CI 以同一组有效/无效 fixture 校验防漂移 |
| M1-02 | 建立后端数据与存储基础 | PostgreSQL 迁移、JSONB 方案数据、AI 任务与调用记录、配额记录；OSS 对象封装与受控访问；密钥仅留后端 |
| M1-03 | 图片上传 | 接收 JPG/PNG/WebP，校验实际文件内容、尺寸和大小；拒收 CAD/DWG/DXF/PDF；原图上传和异常提示可验证 |
| M1-04 | 视觉 Provider 与识别管线 | 标准化请求/响应与错误，校验结构、尺寸一致性和引用关系；处理墙门窗及房间名；按 PRD 降级特殊元素，识别复式时提示不支持；失败提供重试 |
| M1-05 | 异步任务与状态反馈 | 排队、执行、成功、失败状态及 SSE 或轮询；超时和刷新恢复；保留幂等键，避免重复点击产生重复调用 |
| M1-06 | 配额、频控与结算 | 游客每日解析 3 次、生图 3 张，账号每日解析 5 次、生图 10 张；游客设备指纹 + IP 双维限制，账号按账号限制；数据库原子预占和结算，失败不扣，生图自动重试一次 |
| M1-07 | 确定性场景管理层 | 从 JSON 建墙、开门窗洞、建地面；场景资源统一创建/更新/销毁；俯视与行走切换；渲染参数集中配置 |
| M1-08 | 游客本地方案与主流程界面 | 本地持久化、刷新恢复；上传、解析进度、成功进入场景、失败重试和额度提示；游客无需注册可用 |
| M1-09 | 核心闭环验收与监控 | 从上传开始到 3D 首次可用记录端到端耗时；记录识别成功率、Provider 延迟与错误，避免只统计后端耗时 |

出口：用真实户型完成上传 → 解析 → 校验 → 3D，失败不扣额度且可重试；电子图结构可用率 ≥ 80%，上传到 3D 的 P50 ≤ 60s，报告样本与环境。若不达标，先解决质量瓶颈。

### M2：可修正、可布置、可保存分享

依赖：M1 Schema 和场景层稳定；家具资产整理可在 M0 通过后与 M1 并行。

| ID | 任务 | 交付物与验收 |
|---|---|---|
| M2-01 | 编辑状态与命令基础设施 | Pinia 保存规范化方案；统一选择、拖拽、吸附、命令、undo/redo；编辑 JSON 后同步更新 3D，撤销重做覆盖复合操作 |
| M2-02 | 轻量墙体修正 | 俯视下拖动墙端点、删墙、两点加直墙、开关门窗洞；同步维护门窗归属和有效几何，错误操作可撤销 |
| M2-03 | 家具可插拔目录与模型入库 | 精选 50–80 件 CC0 低多边形资产，覆盖六类高频家具/家电；记录来源、许可证证据、模型 ID、尺寸、品类、风格标签和可扩展 SKU 字段；统一单位、朝向、枢轴和风格 |
| M2-04 | 家具编辑交互 | 从品类添加、移动、网格/贴墙吸附、默认 90° 旋转与自由旋转、删除、复制；不提供自由缩放；重叠高亮警告但允许保留 |
| M2-05 | 双视角编辑联动 | 俯视编辑即更新 3D；切换保持方案与选择状态一致，处理画布操作与 UI 焦点冲突 |
| M2-06 | 手机验证码登录 | 验证码发送/校验、发送频控与会话管理；游客点击保存才触发登录；登录后明确迁移当前本地方案，避免覆盖已有云方案 |
| M2-07 | 云存与我的方案 | 创建、更新、读取、列表和权限校验；保存 Schema 版本，处理保存失败与并发版本冲突；后续兼容迁移有入口 |
| M2-08 | 只读分享 | 生成不可猜测分享标识，按确认的快照/更新规则展示；分享读取禁止修改、隔离私有资源和账号信息，支持约定的撤销行为 |

出口：内测用户可以修正墙体、完整增删改家具，撤销/重做后数据与画面一致；50–80 件资产满足尺寸和授权要求；登录后保存、重开、只读分享均可用，不能读取他人私有方案。

### M3：风格效果图与传播闭环

依赖：M0 Spike B 通过，M1 任务/配额/存储可复用，M2 场景与保存分享稳定。

| ID | 任务 | 交付物与验收 |
|---|---|---|
| M3-01 | 自动预设机位 | 基于房间中心与朝向启发式提供 3–4 个可选机位；验证小房间和狭长房间，避免机位落墙或主要视野被遮挡；不提供自由摆相机 |
| M3-02 | 截图与深度输出接口 | 根据选定机位导出场景截图并记录相机参数、方案版本；预留深度图输出通路，以样例确认可输出，不接入 V2 ControlNet |
| M3-03 | 风格参考图与生图 Provider | 校验并上传风格图；发送截图 + 风格图，经后端可替换适配器调用 API；异步进度、失败自动重试一次，失败不扣额度 |
| M3-04 | AI 标识贯穿全链路 | 接入首日起已有的标识模块，确认结果预览、历史、分享和下载都保留显式水印及隐式元数据；校验格式转换不会丢失标识 |
| M3-05 | 结果历史与保存分享 | 历史关联方案版本、机位与任务；可查看、保存、下载并分享结果；用户编辑方案后历史结果仍对应原生成版本 |
| M3-06 | 质量评测 | 以固定评分规程复测布局保持和风格还原，主观可用率 ≥ 60%；记录输入、输出、模型版本与结果，支持复现 |

出口：游客无需注册完成生图；成功结果只扣一次额度，失败重试行为正确；效果图可看、可存、可分享，所有对外结果保留 AI 标识。

### M4：私域内测与价值验证

依赖：M1–M3 验收通过；内测前置条件完成。

| ID | 任务 | 交付物与验收 |
|---|---|---|
| M4-01 | 漏斗埋点与指标报表 | 上传、3D 首次可用、生成成功、主动分享、回访事件；匿名/登录身份衔接、事件去重；分享触发与实际分享访问分开统计 |
| M4-02 | 邀请与政策 | 邀请码或私密入口控制、隐私政策和用户协议；核验内测访问限制、对象存储访问与 AI 标识；同步 ICP 进度 |
| M4-03 | 移动端可看 | 可打开方案与分享、观看场景和效果图；明确移动端编辑边界，不扩展深度优化范围 |
| M4-04 | 性能与稳定性 | 使用最大代表性户型和完整家具目录测加载、帧率、内存与任务恢复；按真实瓶颈优化模型加载、场景资源和截图处理，形成设备/浏览器支持记录 |
| M4-05 | 组织 30–50 名真实业主内测 | 招募、使用反馈与故障收集；保留足够观察期统计次周回访，不以开发测试账号替代真实用户 |
| M4-06 | 输出产品决策报告 | 分开报告质量线与价值线，给出继续投入、回到 Spike 或调整方案的证据 |

验收指标：

- 质量：电子户型图结构可用率 ≥ 80%；效果图主观可用率 ≥ 60%；上传 → 3D 的 P50 ≤ 60s。
- 漏斗：上传 → 看到 3D ≥ 70%；看到 3D → 生成至少一张效果图 ≥ 50%；生成 → 主动分享 ≥ 30%。
- 留存：次周回访 ≥ 20%；北极星指标为分享次数 / 激活用户。
- 内测开始前固化激活、主动分享、次周的定义及统计分母和观察窗口；建议激活以首次成功看到 3D 为基础，最终口径需产品确认。
- 价值线达标后再规划公开版与付费包；质量不达标先回到能力验证。小样本指标同时报告人数与比例。

## 4. 依赖与可并行工作

主依赖链：M0 证据与技术决策 → M1 共享数据和核心闭环 → M2 编辑/存档 → M3 效果图完整闭环 → M4 内测。

- M0 期间可并行推进视觉稿、账号/SMS 与 OSS 服务选型、ICP 材料、隐私政策准备。
- M0 通过后，家具资产收集与标准化可与 M1 并行，不阻塞固定样例场景验证。
- Schema 先稳定基本契约，再并行开发后端识别与前端建模；由共享 fixture 合流验收。
- 编辑命令基础设施先于墙体和家具编辑；账号先于云存权限与只读分享验收。
- 配额架构在 M1 同时覆盖两类 AI 任务，正式生图业务在 M3 接入；不能到 M3 才补计数设计。
- AI 标识在 M0 生图 Spike 即落地，M3 负责生产链路覆盖和传播校验。
- 埋点事件定义可在 M1 确定并逐步接入，M4 完成报表与真实用户验证。

## 5. 验证策略与阶段完成规则

优先验证高风险契约与业务行为，不为静态界面文案堆叠测试。

| 验证面 | 重点 |
|---|---|
| Schema 契约 | 同一组 fixture 在 TS/Pydantic 双端结果一致；单位、坐标、引用和版本一致 |
| 几何与编辑 | 门窗开洞位置、墙端点更新、真实尺寸、吸附与旋转；undo/redo 能恢复完整数据；重叠只警告 |
| AI 与配额 | Provider 契约、结构异常、超时、重复提交、并发争抢最后额度、跨日、重试、失败释放与成功单次结算 |
| 账号与分享 | 游客本地恢复、登录迁移、私有方案权限、只读能力、撤销规则与 OSS 资源访问 |
| 生图与标识 | 固定输入回归、相机与方案版本关联、下载/分享标识保留、历史可恢复 |
| 端到端体验 | 游客走完全流程，保存触发登录；刷新和失败恢复；桌面编辑与移动观看 |
| 质量与性能 | 真实样本人工评分、端到端 P50、代表性户型负载；记录环境与样本，不能用 mock 替代真实 API 的能力验证 |

每个阶段完成须同时具备：可运行产物、使用说明、对应验收记录、未解决问题及影响。PR/CI 通过只能证明工程检查通过，不能替代产品质量与商业价值验证。

## 6. 范围边界与风险处理

V1 不纳入：CAD/PDF 矢量解析、完整画户型、自由缩放、碰撞硬阻止、堵门检测、生成式 3D 家具、风格实时应用到 3D、飘窗/柱子/复式专项建模、自由相机、ControlNet、支付、B/D 端交互、移动深度优化、微信扫码登录。

- 无尺寸标注：明确失败并提示重试，不估算真实尺寸；点墙标定保留为 V1.1，不提前加入本期。
- 模型供应商质量或服务变化：依靠适配层、可复现输入和错误分类切换；先验证再变更。
- 生图布局保持不足：先复测供应商与输入策略；提前引入深度控制必须更新决策及计划。
- 超过 60s：异步进度改善等待体验，但不能代替 P50 指标达标；分别观察排队、上传、识别和渲染耗时。
- 家具来源/尺寸不合格：替换资产并保存来源证据；不可通过前端随意缩放掩盖。
- 公开推广：在价值验证后另立发布与商业化计划，完成 PRD 对应的合规安排。

## 7. 首批执行顺序

1. 准备 10 张真实样本与人工评分表，确定 Spike A/B 的可用判定。
2. 配置验证环境与候选 AI Provider，运行两个独立 Spike，并保存结果与调用成本。
3. 并行完成固定 JSON 的 Three.js 双视角原型和 monorepo 基础。
4. 评审 M0 证据，收敛本计划第 2 节中 M1 前必须确认的事项，决定推进或继续验证。
5. 按 M1 → M2 → M3 → M4 的依赖推进，逐阶段留存验收证据。
